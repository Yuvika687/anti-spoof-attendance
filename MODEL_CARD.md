# Model Card: Liveness Gate (MobileNetV3-Small, v2)

This card describes the deployed liveness-classification model: Stage 2 of
the two-stage anti-spoofing pipeline (Stage 1 is MediaPipe BlazeFace face
detection, not a trained model). Every number below is pulled from
`results/summary.json`, generated by `src/build_summary.py` from the actual
evaluation runs — none are estimated. Regenerate that file and re-pull
these numbers after any retrain.

## Model details

- **Architecture:** MobileNetV3-Small backbone (ImageNet-pretrained,
  fine-tuned) + a small linear head, outputting a single spoof logit.
  1,000,993 parameters, 3.95MB checkpoint.
- **Task:** Binary face liveness classification (LIVE vs. SPOOF) on a single
  cropped face image, with a third **UNCERTAIN** state produced by a
  separate post-hoc decision rule (see "Three-way decision" below) — not a
  third model output class.
- **Input:** A 224×224 BGR face crop, produced by MediaPipe BlazeFace
  detection + a 25% margin crop (`src/face_utils.py`). The model was never
  trained on, and should not be fed, raw uncropped frames — see
  "Known limitations" below.
- **Output:** `sigmoid(logit)` = P(spoof) ∈ [0, 1]. Decision threshold 0.5
  by default (tunable without retraining).
- **Framework:** PyTorch (deployed), also exported to ONNX for CPU
  inference (`src/export_onnx.py`).
- **Version:** v2 (face-crop-trained). An earlier v1 checkpoint exists
  (raw-frame-trained) and is kept only for comparison, not deployed —
  see "Why v2 exists" below.
- **Alternatives evaluated, not deployed:** ResNet-18 and EfficientNet-B0,
  same training recipe, same data. See the Models page of the web
  dashboard or `results/summary.json`'s `backbone_comparison` section for
  the full comparison; EfficientNet-B0 measures a lower HTER but
  MobileNetV3-Small is far smaller and faster under ONNX Runtime on CPU,
  which is why it is the one deployed.

## Intended use

- A liveness-checking gate in front of a face-recognition attendance
  system: reject printed-photo, screen-replay, and mask/poster
  presentation attacks before a frame reaches face recognition.
- Designed to run on a live webcam feed at interactive frame rates
  (Stage 2 inference alone: ~6.6ms on Apple Silicon MPS, ~2.8ms under
  ONNX Runtime on CPU — see `results/backbone_latency.json`).
- **Not** intended as a identity-verification or face-recognition model
  itself — it only answers "is this a live human face," not "whose face
  is this."

## Training data

- **CelebA-Spoof** (Zhang et al., ECCV 2020), research-only,
  non-commercial license. This repository's mirror of the dataset has
  9,196 identities / 561,575 images (~90% of the paper's published
  release — see the README's dataset note).
- An identity-disjoint subset was built: 18,200 training images / 3,900
  validation images / 3,900 test images, no identity appearing in more
  than one split (`src/prepare_celeba_subset.py`).
- Labels were cross-checked against CelebA-Spoof's own official
  `metas/*.json` ground truth (not just the live/spoof folder an image
  was filed under) — this corrected 2,022 images' labels before training.
- **v2 specifically** was trained on face crops built by
  `src/build_face_cropped_dataset.py`, using the exact same BlazeFace
  detection + 25% margin crop function the live deployment pipeline
  uses. Where BlazeFace could not detect a face in the raw training
  image, the dataset's own official bounding box was used as a fallback
  (61/3,900 test-split images, 1.56%) — see "Why v2 exists" below for why
  this crop step matters.

## Evaluation data and metrics

Canonical protocol: the full 3,900-image CelebA-Spoof test split (held
out, no identity overlap with train/val), deployment-style face crops
(BlazeFace detection + 25% margin, falling back to the dataset's own
official bounding box on a detection miss), plain 0.5 threshold.

| Metric | Value |
|---|---|
| Accuracy | 98.69% |
| APCER (attacks wrongly accepted as live) | 1.38% |
| BPCER (genuine faces wrongly rejected) | 1.23% |
| HTER | 1.31% |

**Weakest attack types** (highest APCER, i.e. most likely to be wrongly
accepted as live): PC-screen replay (3.06%, n=229), Pad-screen replay
(2.22%, n=180), Phone-screen replay (1.91%, n=209). All ten CelebA-Spoof
attack types (printed photo, poster, A4-paper, phone/pad/PC replay, 3D
mask, and three paper-mask/region/upper-body attack types) are evaluated
individually — see `results/summary.json`'s `breakdowns` section or the
Robustness page of the web dashboard for the full per-type, per-
illumination, and per-environment tables.

## Three-way decision (gray zone)

In deployment, P(spoof) is also compared against an UNCERTAIN band
selected on the **validation** set only (never test), currently
`[0.0242, 0.9758]`. Applied to the test set: 95.13% of samples still get
a confident LIVE/SPOOF decision (HTER on that decided subset: 0.22%);
the remaining 4.87% are flagged UNCERTAIN rather than returned as a
possibly-wrong answer. This band specifically catches 24 of the 27 real
false accepts and 19 of the 24 real false rejects that the plain
threshold gets wrong.

## Known limitations

- **Crop-dependent.** The single most important limitation: this model
  was trained on, and must be fed, face crops from the exact same
  BlazeFace-detect + 25%-margin pipeline used in training
  (`src/face_utils.py`'s `crop_face`). An earlier version (v1) was
  trained on raw uncropped frames and measured 94.54% accuracy / 5.46%
  HTER when evaluated through the real deployment crop instead — a
  large, real gap, not a rounding difference. Do not feed this model
  raw, uncropped images.
- **Synthetic masked-face gap.** Evaluated against synthetic
  surgical-mask overlays (white/light-blue/black, nose-to-chin, applied
  via `src/synthetic_mask.py`'s MediaPipe FaceLandmarker-based overlay)
  rather than photos of people in real surgical masks: HTER rises from
  0.97% unmasked to 1.57% masked under matched methodology. This is a
  real, measured effect but has not been validated against real
  photographs of masked faces, and the synthetic mask itself fails to
  render on 171/3,900 (4.4%) of raw images (landmark detection failure
  on those faces) — those are excluded from the masked-eval numbers
  above, not silently treated as passes.
- **Single-dataset training.** Trained and evaluated entirely within
  CelebA-Spoof's own capture distribution (its cameras, lighting,
  attack props). Cross-dataset generalization (e.g. to CASIA-FASD) and
  real-world webcam performance (the actual deployment camera, room,
  phone/printer) have not yet been measured — both are open items in
  the project roadmap, not validated claims.
- **Attack-type imbalance.** Per-attack-type sample counts range from
  n=172 to n=229 in the test set; breakdown numbers below roughly n=50
  are flagged low-confidence in the underlying breakdown script and
  should not be over-interpreted individually.
- **Two-class liveness only.** Does not attempt identity verification,
  age/gender inference, or any attribute beyond live/spoof.

## Ethical considerations

- CelebA-Spoof is a research-only, non-commercial dataset; any model
  checkpoint trained on it inherits that restriction (see `LICENSE`).
- This is a presence/liveness gate, not an identity or demographic
  classifier — it was not evaluated for differential error rates across
  demographic groups, and such an audit should be done before any
  production use, particularly given CelebA-Spoof's own known
  demographic skew as a celebrity-photo dataset.
- A false accept (APCER) lets a spoofed/attacked presentation through to
  the next pipeline stage; a false reject (BPCER) inconveniences a
  genuine user. The UNCERTAIN band is a deliberate choice to trade some
  coverage for fewer confident wrong answers in both directions, rather
  than tuning the threshold to favor one failure mode silently.
