Technical Pipeline

How It Works

Two stages: a mask-aware face detector, then a binary liveness classifier. Both are real, running models — not simulated.

Stage 1 · Mask-Aware Face Detection

MediaPipe's BlazeFace short-range model localizes faces primarily from upper-face landmarks (eyes, eyebrows, nose bridge), so it keeps working when a mask covers the mouth and nose. It outputs 6 keypoints, not a dense mesh.

Stage 2 · CNN Liveness Classifier

A MobileNetV3-Small backbone (ImageNet-pretrained, fine-tuned end-to-end) scores the cropped face as LIVE or SPOOF. It outputs one number — P(spoof) — nothing else: no attack-type classification, no mask-type classification, no depth or blink analysis. Single RGB frame in, one probability out.

Training Data

Evaluation Metrics

Reported using the standard presentation-attack-detection metrics: APCER (spoof wrongly accepted as live), BPCER (live wrongly rejected as spoof), and HTER = (APCER+BPCER)/2.

About the FPS numbers

The 26.7 FPS figure shown on Overview/How It Works was measured by calling the detection + classification functions directly in Python, with no browser, network, or JPEG-encoding overhead. The Web round-trip FPS above is the real, slower number for this actual page: camera capture → JPEG encode → HTTP upload → Flask → model → JSON response → render, measured live, right now.
